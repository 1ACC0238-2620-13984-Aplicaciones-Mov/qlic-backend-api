# qlic-backend-api

RESTful API of **Qlic** (startup WASD) — UPC 1ACC0238 Mobile Applications.

## Stack

| Item | Version |
|---|---|
| Language | Kotlin 2.3 on the JVM (toolchain 24) |
| Framework | Spring Boot 4.1 (Web MVC, Data JPA, Validation, Security OAuth2 Resource Server) |
| Documentation | springdoc-openapi 3.1 (OpenAPI 3 + Swagger UI) |
| Database | In-memory H2 (`dev` profile) · PostgreSQL (`prod` profile) |
| Build | Gradle Wrapper 9.7 (Kotlin DSL) |

## Implemented bounded contexts

| Bounded context | Stories | Endpoints |
|---|---|---|
| IAM | US05, US06, TS01 | `POST /api/v1/authentication/sign-up` · `POST /api/v1/authentication/sign-in` |
| IAM | US07 | `POST /api/v1/authentication/password-reset/request` · `POST /api/v1/authentication/password-reset/confirm` |
| IAM | US08 | `POST /api/v1/invitations` · `GET /api/v1/invitations` · `GET /api/v1/invitations/received` · `POST /api/v1/invitations/{id}/acceptance` · `GET /api/v1/authorized-users` · `DELETE /api/v1/authorized-users/{id}` · `GET /api/v1/accounts/shared-with-me` |
| IAM | US09 | `GET /api/v1/accounts/me` · `PUT /api/v1/accounts/me` |
| Device Monitoring | US10, US11, US12 | `POST /api/v1/devices` · `PATCH /api/v1/devices/{id}/water-point` · `GET /api/v1/devices` · `POST /api/v1/consumption-readings` |
| Alerting | US15-US20 | `POST /api/v1/alerts/evaluations` · `GET /api/v1/alerts` · thresholds, preferences and recipients |
| Subscriptions | US31-US34 | `POST /api/v1/subscriptions` · `POST /api/v1/subscriptions/trial` · `GET /api/v1/subscriptions/current` · `GET /api/v1/subscriptions/payments` |
| Consumption Analytics | US24 | `PUT /api/v1/consumption/activity-schedule` · `GET /api/v1/consumption/activity-schedule` · `GET /api/v1/consumption/reports/activity-hours` |
| Support | US35, US36, US37 | `POST /api/v1/incidents` · `GET /api/v1/incidents` · `GET /api/v1/incidents/{id}` · `POST /api/v1/incidents/{id}/technical-visit` · `POST /api/v1/incidents/{id}/technical-visit/assignment` · `POST /api/v1/incidents/{id}/resolution` · `GET /api/v1/technicians` |
| Support | US38 | `GET /api/v1/terms-of-service/current` |

The `authentication` and `terms-of-service` endpoints are public; every other endpoint requires the header `Authorization: Bearer <token>` (`401` without token). The token carries the account and the permission level of the session: a user invited with `VIEWER` permission gets `403` on `POST`, `PUT`, `PATCH` and `DELETE` over devices, alerts, consumption, incidents and subscriptions (US08). To work on an account shared with you, send its `accountId` in the sign-in request. IAM messages are in English by default; send `Accept-Language: es-419` to receive them in Latin American Spanish.

## Run locally

```bash
./gradlew bootRun     # dev profile (H2)
./gradlew test        # unit and integration tests
```

- Swagger UI: http://localhost:8080/swagger-ui.html
- OpenAPI JSON: http://localhost:8080/v3/api-docs
- H2 console: http://localhost:8080/h2-console (JDBC URL `jdbc:h2:mem:qlicdb`, user `sa`)

## Deployment (Render, Docker + PostgreSQL)

The `Dockerfile` builds the JAR with JDK 24 and runs it on JRE 24 using the `PORT` assigned by Render. The `render.yaml` Blueprint creates the web service and a managed PostgreSQL database and wires them together: in Render select **New > Blueprint**, choose this repository and confirm. Every merge to `main` triggers a new deployment.

| Variable | Value |
|---|---|
| `SPRING_PROFILES_ACTIVE` | `prod` |
| `DB_HOST` / `DB_PORT` / `DB_NAME` | Injected from the Render database (`fromDatabase`) |
| `SPRING_DATASOURCE_USERNAME` / `SPRING_DATASOURCE_PASSWORD` | Injected from the Render database |
| `SPRING_DATASOURCE_URL` | Optional; overrides the URL built from `DB_HOST`, `DB_PORT` and `DB_NAME` |
| `JWT_SECRET` | HS256 signing key, at least 32 characters (generated by Render) |
| `JWT_EXPIRATION_MINUTES` | Token lifetime (default 1440) |
| `PASSWORD_RESET_EXPOSE_TOKEN` | `true` returns the reset token in the response while no email provider is configured |

Hibernate creates and updates the tables (`ddl-auto=update`). The Support data seeder loads the technicians and the terms of service the first time the application starts against an empty database.
